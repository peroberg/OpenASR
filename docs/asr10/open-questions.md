# ASR-10 open questions

This file tracks unresolved questions. Do not treat anything here as confirmed fact.

Current main blocker:

```text
The emulator reaches ENSONIQ ASR-10 / LOADING SYSTEM, then returns to firmware dispatcher idle around f87f96/f87f9a. The next missing piece is likely dispatcher event payload, timer cadence, queue re-arm, or hardware-side completion semantics after the accepted-looking MC68302 0x2400 service sequence.
```

- What do queue slot byte2 and byte3 represent?
- Which slot is slot 2, and why is it cleared at `f87fb0` before/around the `00bf1a` service setter?
- Which callback/handler pointer is associated with slot 2?
- What is the last real non-idle queue event before final dispatcher idle?
- Which code path should re-arm a dispatcher slot after the `00bf1a` / `$0d06` service sequence?
- Is the missing next event generated by a timer, a hardware completion bit, a panel event, an FDC event, or a software queue mutation?

## MC68302 / service lifecycle

- What is the exact meaning of FC6814 bit `0x2400`?
- What is the exact meaning of FC6816 bit `0x2400`?
- Is FC6816 `0x2400` an in-service latch, service-active flag, EOI state, or firmware-owned software mirror?
- What is the exact role of FC6818 writes:
    - `4000` from vector `0x4e`
    - `8000` from vector `0x4f`
    - later return to `0080`
- Are vectors `0x4e` and `0x4f` both valid for related sources, or is one only accidentally tolerated?
- Which MC68302 interrupt source maps to vector `0x4e`?
- Which MC68302 interrupt source maps to vector `0x4f`?
- Does the 68302 interrupt controller need a real in-service/EOI state machine?
- Does the runtime expect a periodic timer tick rather than a one-shot service interrupt?
- Low priority: why do Lua passthrough taps see zero accesses in
  `$FC6000-$FC6FFF` while the `$0067EC` channel-select path is otherwise
  proven to execute? In the 2026-08-03 PAR Lua observe run,
  `fallande_PC=006802` and `$0DD6-skrivningar: 3` prove execution through
  `$0067F6`/`$006800`, but the tap census was
  `FC20xx x1128`, `FC30xx x15`, `FC40xx x1875886`, `FC48xx x3092`,
  `FC50xx x2`, with no `FC68xx`, and both
  `68302-LAS $FC6000-$FC6FFF` and `68302-SKRIV $FC6000-$FC6FFF` were empty.
  Treat this as a tap/dispatch-layer question, not hardware evidence.
